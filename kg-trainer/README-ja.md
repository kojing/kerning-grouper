# Kerning Grouper 学習ツール（kg-trainer）

プロのフォント（OTF/TTF）のカーニングを正解として、Kerning Grouper の
カーニング計算の設定と補正モデル、グループ作成の設定を学習するツールです。
ブラウザで操作しますが、サーバーはこの PC の中（127.0.0.1）だけで動きます。
フォントやデータは外に送られません。

## 必要なもの

- Python 3.10 以上
- fontTools と numpy：`pip install fonttools numpy`
- 値の補正モデルを作る場合は scikit-learn：`pip install scikit-learn`
- テストを動かす場合だけ playwright（`pip install playwright` と `playwright install chromium`）

## 起動

```
cd kg-trainer
python -m kg_trainer            # ブラウザが開きます（http://127.0.0.1:8765/）
python -m kg_trainer --port 9000 --no-browser
```

ポートが使用中のときは、空いているポートで起動します。終了は Ctrl+C です。

## 使い方

1. **学習元フォント**：OTF/TTF をドロップします（複数可）。フォントごとに
   - ライセンス（例：OFL 1.1、自社フォント）を書きます。モデルに学習元として記録されます。
   - 「使う」のオン／オフで、学習に入れるかを選びます。
   - 対象の字（かな・欧文・数字・欧文約物のプリセットあり）、基準の字、最小の字間を決めます。
2. **正解データ**：各フォントから読めたカーニングのペア数、クラス数、palt、読めなかったルックアップを確認します。
3. **評価・学習**：「学習する」で、今の計算・設定だけ学習・学習したモデルの3つを、プロの値と比べます。
4. **グループ**：プロのカーニングクラスとグループ作成の判定がどれだけ一致するか（F1）と、いちばん近い設定を見ます。
5. **書き出し**：モデル（`.kgmodel.json`）を保存します。フォントのアウトラインは入りません。

## 複数のフォントで精度を上げる

- フォントが2つ以上あると、**フォント単位の1つ抜き**で検証します。1書体を外して残りで学習し、
  外した書体で誤差を測ります。数字は「まだ見たことのないフォントでの精度」です。
  1書体だけのときは、同じフォントの中で先頭の字ごとに分けた 5 分割で測ります（甘めの数字になります）。
- 学習では**フォントごとの重みを揃えます**。ペアの多い1書体に引っぱられません。
- **学習に使うフォントの数と精度**のグラフで、書体を足すほど誤差が下がっているかを確かめられます。
  まだ下がっていれば、さらに足す価値があります。横ばいなら、数より「仕上げたいフォントに近い書体」を選ぶほうが効きます。
- **フォントごとの精度**で「偏り」が書体ごとに大きく違うときは、詰め具合の方針が混ざっています。
  方針の近い書体だけを「使う」にしてください。学習したモデルが今の計算より悪くなったときも同じです。
- カーニングがほとんどないフォントは、ほぼすべてのペアが「0 が正解」として学習され、全体を緩める方向に引っぱります。
  画面に注意が出るので、外すのがおすすめです。

## Web 版の値の補正モデル（欧文）

Web 版 v0.5.2 は、英字どうしのペアの値の大きさを学習モデル（`src/kern-model.js`）で決めます。このモデルを、登録したフォントで作り直せます。

- 画面：「評価・学習」タブの下「Web 版の値の補正モデル」→「補正モデルを学習する」→「kern-model.js を書き出す」。
- コマンド：`python -m kg_trainer.build_value_model フォント... -o kern-model.js --eval`
- 書き出した `kern-model.js` を Web 版の `src/kern-model.js` と差し替えて `node build.mjs` でビルドすると反映されます。
- 学習に使うのは、プロもツールも値を入れている英字のペアです。2書体以上あると、1書体を外した精度を表示します。今の同梱モデル（OFL 12書体）は、知らない書体で誤差 24.4 → 15.6 でした。
- 特徴量は `kg_trainer/valuemodel.py`。Web 版の `src/kerning.js`（valueFeatures・predictValue）と1対1で、`tests/test_parity.py` で一致を確かめます（`KG_PARITY_FONT=実フォント` で実フォントも）。scikit-learn が必要です（`pip install scikit-learn`）。

## 読めるもの・読めないもの

- GPOS の kern 機能の PairPos（フォーマット 1/2、クラス 0、拡張ルックアップ）。ルックアップをまたぐ値は足し合わせます。
- GPOS がない場合は旧 kern テーブル（フォーマット 0）。
- 文脈依存のカーニング（チェイン文脈など）は読み飛ばし、「読めなかった部分」に表示します。
- 可変フォントは既定のインスタンスだけを使います。
- palt は学習に使いません（kern の値だけを正解にします）。
- 値はすべて 1000 UPM に揃えて比べます。誤差 28 が 18px 表示での半ピクセル、56 が1ピクセルです。

## ライセンスについて

学習に使えるのは、ライセンス上許されたフォント（OFL のフォントや自社フォントなど）だけです。
市販フォントの多くは、解析や派生物の作成を禁じています。使う前に必ず使用許諾を確認してください。

## モデルの中身（.kgmodel.json）

`format: "kerning-grouper-model"`、`version: 1`。主な項目：

- `kerning.settings`：光学の割合・上限・基準の字・最小の字間
- `kerning.kindOffsets`：ペアの種類ごとの字間の補正
- `kerning.residual` / `kerning.uncertainty`：補正と、予想される誤差のリッジ回帰（特徴量名つき）
- `grouping`：グループ作成のいちばん近い設定と一致率
- `trainingFonts`：学習元のファイル名・ファミリー名・SHA-1・ライセンス
- `coreVersion` / `featureVersion`：Web 版の計算と合っているかの確認用

## テスト

テストは、隣に `kerning-grouper/`（Web 版。サンプルフォントと JS の計算）がある前提です。引き継ぎ用 zip ならそのまま動きます。

```
python -m unittest discover -s tests -p "test_*.py"
```

- `test_parity.py`：Python の計算が Web 版（JS）と完全に一致するか（node と Web 版のソースが必要）
- `test_fontio.py`：クラス・個別・拡張ルックアップ・palt の読み取り
- `test_model.py`：既知の関係を学習で取り戻せるか
- `test_multifont.py`：複数フォントの1つ抜き・重みの均等化・フォントごとの精度・書体数と精度
- `test_gui.py`：ブラウザ画面の一連の操作（playwright）

## 優先度モデル（v0.5.6）
`python -m kg_trainer.build_priority_model FONT... -o ../kerning-grouper/src/priority-model.js --eval` で、「プロがこの組にカーニングを入れるか」を学習したモデルを作ります（ASCII と主な引用符・ダッシュ、値 10 以上を「入れる」）。特徴量は値のモデルの 116 個と、両方の字の種類（大文字・小文字・数字・引用符・句読点・ダッシュ・かっこ・スラッシュ・その他の記号・それ以外）。Web ツールと 1:1 で同じ値になることを tests/test_parity.py で確認します。ライセンスが許す書体（OFL・自社）だけを使ってください。
