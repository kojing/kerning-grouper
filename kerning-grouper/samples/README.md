# 和文検証サンプル

`KGJapaneseTest-Regular.ttf` は Noto Sans JP（wght=400の静的版）から、検証用の174文字（ひらがな・カタカナ・約物、漢字なし）とASCII（U+0020〜U+007E）に限定した派生フォントです（270グリフ）。原版と区別するため内部名を KG Japanese Test に変更しています。ライセンスは同梱の NotoSansJP-OFL.txt（SIL OFL 1.1）です。

v0.5で欧文を追加して作り直しました。和文174字の輪郭と送り幅はv0.4のサンプルと同一であることをfontToolsで確認済みです（差分0）。v0.5の取得元：npm `@expo-google-fonts/noto-sans-jp@0.4.4` の `NotoSansJP_400Regular.ttf`（Google Fonts配布のNoto Sans JP、OFL）。fontTools 4.65で抽出。

原版: https://github.com/google/fonts/tree/main/ofl/notosansjp
取得元: https://raw.githubusercontent.com/google/fonts/main/ofl/notosansjp/NotoSansJP%5Bwght%5D.ttf
取得日: 2026-10-14 UTC

## 操作
1. standalone.html を開き、同梱TTFを読み込む。
2. タブ「1 対象グリフ」でひらがな・カタカナ・和文の約物の規則にチェック→タブ「2 グループ作成」で「グループを作成」（必要なら「3 グループ調整」で分離・統合）。
3. タブ「4 カーニング生成」で「カーニング生成」（和文のみなら和文の基準ペアに自動で切り替わります）。
4. 比重・余白・省略閾値を調整し、タブ「5 カーニング調整」で補正前後を比較。
5. タブ「6 保存」で FontLab 用 VFM／CSVを書き出す。

対象は「1 対象グリフ」のUnicodeの規則（ひらがな・カタカナ・和文の約物・英大文字など）で選び、外したい文字は「除外する文字」に入力します。未収録文字はステータスで通知します。空白・結合マーク等は解析対象外です。大きい和文フォントでは1回の分類800グリフ、生成320グリフ、読込20000グリフという上限に注意してください。Google Fontsの可変TTFをそのまま読み込む機能は未対応です。同梱フォントは開発時にfontToolsで変換してあり、利用時の追加インストール・外部通信は不要です。

## 検証の意味と限界
`node test-japanese.mjs` は実輪郭に対して分類・全ペア生成・数値有限性・接触回避のモデル下限を検証します。結果はvalidation.json。

v0.5.0 の初期条件では174文字（ひらがな・カタカナ・約物、漢字なし） / 30276ペア、先頭174・後ろ172グループ、モデル概算63142 bytesで64KiB以内の概算です（実出力の保証ではありません）。形状閾値が欧文向けに厳しいため、ほぼ単独グループです。生成警告5071件は補正上限等の条件を表し、失敗件数ではありません。

和文のかな・カタカナ・約物は現行エンジンでは同じ基準カテゴリです。基準ペアは調整開始用の仮設定で、組版的な正解ではありません。モデル誤差の減少は見た目の改善を保証しません。特に句読点・括弧・小書き文字・長音は目視校正が必要です。ベタ組み、禁則処理、縦組み、palt/vpal、既存GPOSの重ね適用は再現しません。プレビューは素のアドバンス幅＋生成値です。

64KiBはVFMファイル自体の上限ではありません。本ツールの容量はGPOS構造を仮定した概算です。実際のFontLab出力の検証、VFM書き出しは未実装です。

## FiraSans-Regular-subset.ttf（v0.5.6 追加）
- Fira Sans Regular（SIL Open Font License 1.1、ライセンス全文は FiraSans-OFL.txt）から、ASCII・ラテン文字（U+00A0–024F）・ギリシャ文字（U+0370–03FF）・キリル文字（U+0400–04FF）・一般句読点・通貨記号・№ ™ ← ↑ → ↓ だけを残したもの（fontTools pyftsubset、レイアウト機能はすべて残す）。
- 欧文・ギリシャ文字・記号を含む書体の確認用。アーティファクトのデモでは「サンプル：欧文・ギリシャ・記号」で、英大文字・英小文字・数字・ASCII記号・ギリシャ文字・その他の記号（275 字）を選んでグループ作成とカーニング生成まで進めます。
